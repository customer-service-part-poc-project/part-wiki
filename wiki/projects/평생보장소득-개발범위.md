## 시뮬레이터 논점 (2026-09-11 정리)
개발 스코프에 시뮬레이터가 들어갔지만, 기획 기준으로는 2차 보고에서 빠진 기능이다.

| 시점 | 솔루션 | 시뮬레이터 |
|---|---|---|
| 1차 보고 | 상품 추천에 한정 | **있음** — 고객이 직접 값 조정 |
| 2차 보고 | 플랜에 대한 솔루션 제공 | **없음** |

**결론**: 보고는 2차 기준으로 간다. 구현 단계에서 다시 검토한다.
- [[이강민]]: "보고 때는 핵심 컨셉이 드러나면 되고, 실제 구현할 때 넣으면 될 것 같다.
  이용자 관점에서 상세 시뮬레이션은 꼭 필요할 거 같다"
- [[이정은]]: "지금 보고는 2차 기준으로. 상세기획 들어갈 때 더 고민. 저도 있으면 좋을 것 같다"
- 배치 아이디어: '은퇴플랜수정'에 들어가면 부가기능으로 시뮬레이터를 두는 방식

## 회의에서 정해진 범위 (2026-09-10~11 추정)
| 항목 | 결정 |
|---|---|
| **인출(수령 계획)** | 포함하되 **MVP 1차 제외, 2차**. 큰 그림에는 담고 "세부는 쪼개서" |
| 국민연금 변수 조정 (조기/연기) | 1차는 **종신·65세 고정값**. 평균소득 등 추가 입력은 나중에 |
| 주택연금 집값 | **수동 입력** (마이데이터에 주소 없음) |
| 데이터 원천 | **쿠콘** 계약 경유. 마이데이터 사업자 직접 취득은 제외 |
| 회원가입 | **소셜 로그인(카카오·애플) 검토.** 시그널 스노우볼도 소셜. 금융 서비스 제약 확인 필요 |
| AI 추천 | 옆에 인사이트로 띄우는 안 — "구현이 제일 쉽다" |
| 배포·검증 | 외부 베타는 불필요. **기능 단위 사내 배포**로 검증 ([[이강민]], 9/15). 첫 스텝 산출물부터 사내에 돌리며 이어서 개발 |
