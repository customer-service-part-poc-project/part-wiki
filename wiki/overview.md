# 고객서비스 파트 개요

한 장으로 보는 파트 현황. 위키의 허브 — 여기서 각 영역으로 링크를 따라간다.

## 파트

한화생명 **COE부문 디지털프로덕트팀** 산하 [[고객서비스파트]]. 10명 전원 확인 (2026-09-15).
UX 기획(UXM)·디자인(UXD)·개발(BE/FE/Android)이 한 파트에 있는 **프로덕트 조직**이다.

### 평생보장소득 한눈에
> "은퇴 후에도 당신이 받던 월급을 계속 받게 한다."
> 4050세대가 쌓은 목돈을 평생 월급으로 전환하도록 돕는 **단독 서비스**.
> 시뮬레이션 대신 **플랜 선택 → 역산 가이드** 구조. 사업계획서 제목은 **"평생보장월급 플랫폼"**.

핵심 제약 다섯:
1. 마이데이터 API는 **예상수령액을 주지 않는다** → 국민연금은 **쿠콘 스크래핑**으로 해결, 퇴직·개인연금은 직접 계산 ([[마이데이터-연금정보]])
2. **배우자 정보를 대리 수집할 수 없다** → 각자 인증 후 합산만 ([[부부합산-마이데이터-제약]])
3. **투자자문업 저촉 여부**가 최대 쟁점 — 한화생명은 과거 기관경고 이력. COE Agile과 논의 중 ([[규제-법무-검토항목]])
4. **솔루션을 누가 정하나** — 연금 전문가 없이 파트가 정하면 근거가 빈약하다. 사업화 시 협조 요청 ([[2026-09-파트회의-클로바노트-3세션]])
5. **공공 마이데이터 목적 승인** — 행안부가 "솔루션 제안" 목적을 인정할지 ([[공공-마이데이터]])

지금 논의 중: [[출시-시점-검토]] · [[웹-vs-앱-제공형태]] · [[공통-모듈-개발-검토]]

## 연금 도메인 지식
파트가 리서치로 쌓은 자산. 과제가 바뀌어도 남는다.

- [[주택연금]] — 제도, 연소자 기준, 월지급금표, 시나리오별 유불리, HF API
- [[마이데이터-연금정보]] — 항목별 수신 범위와 계산 책임 범위
- [[부부합산-마이데이터-제약]] — 신용정보법상 가능/불가능 경계
- [[연금-세제]] — 세액공제·ISA·퇴직소득세 이연·종합과세 기준
- [[통합연금포털]] — 연동 방안 (조사 중)
- [[공공-마이데이터]] — 정부24·행안부. 주택연금·국민연금 정보 확보 후보, 목적 승인이 관건
- [[은퇴설계-데이터-출처]] — 자산 항목별 어디서 가져오나. DB형 퇴직연금·전세보증금은 수동 입력
- [[경쟁-서비스]] — 시그널 스노우볼·뱅크샐러드 등 비교 대상
- [[연금-용어]] · [[사내-용어]] — 모르는 단어가 나오면 여기

- [[정기-회의]] — **스크럼 매회 10:30** (월·화·목 확인, 10월 말까지), **월 13:10 팀장 주간회의**

- [[근태-공유]] — 파트방에 태그 형식 사전 공유
- [[과제-검토-분담]] — 초안 공유 후 자율 선착순 분담
- [[협업-도구-현황]] — **슬랙 종료(9/15).** 텔레그램 3개 방 + 노션(문서 정본, 공유 당일 업로드) + 팀즈(파일)
