## 결론부터 — 마이데이터 API로는 예상수령액이 안 온다

> ⚠️ **2026-09-11 정정**: 처음엔 "예상수령액은 어디서도 안 온다"고 정리했다.
> 그러나 **국민연금 예상액은 벤더 스크래핑으로 가져올 수 있다**는 것이 확인됐다 ([[전승찬]] 조사).
> 아래 표는 **마이데이터 API 기준**이고, 국민연금은 별도 경로가 있다. → "국민연금은 스크래핑으로" 절

| 항목 | 오는 것 | 안 오는 것 |
|---|---|---|
| IRP · DC형 | 잔액, 평가금액, 납입원금, 연금개시(예정)일 | **예상수령액** |
| **DB형** | **보유 여부(Y/N) 하나뿐. 적립금도 없음** | 나머지 전부 |
| 연금저축(보험) | 연금개시일, 수령주기 | **예상 연금액** |
| 국민연금 | 납부내역(가입기간·기준소득월액) 수준 | **예상연금액** |

DB형은 보유 여부만 오므로 **평균임금 × 근속연수를 사용자에게 입력받거나 자체 산식이 필수**다.
9/15 스크럼에서 재확인: DB형은 회사 정보를 알 수 없어 **수기 입력**(근속연수 + 최근 3개월 평균 임금)이 유일하다. 전세보증금도 같은 처지 ([[2026-09-15-스크럼-클로바노트]]) → [[은퇴설계-데이터-출처]]

## 국민연금은 스크래핑으로 — 쿠콘 / 코드F

마이데이터로는 국민연금이 안 온다. 그런데 **시장에서는 다들 가져오고 있다.**

| 항목 | 내용 |
|---|---|
| 방식 | 서비스 내 인증 → 인증 데이터를 벤더에 전달 → 벤더가 공단에 로그인한 것과 같은 화면을 스크래핑 → API로 반환 |
| 선례 | 시그널플래너(마이데이터 사업자)도 국민연금은 **코드F**(헤비팩토리 산하 벤더)가 스크래핑 |
| 우리 | **쿠콘과 계약 예정** (담당: 정미님). 쿠콘도 같은 솔루션을 갖고 있다 |
| 받는 항목 (알려진 것) | 예상 연금액 · 총 예상 가입기간 · 수령 시작 연월 · 기본 연금액 · 지급률 · 총 예상 납부 보험료 |
| ⚠️ | **실제 스펙은 명세를 봐야 안다.** 쿠콘 문서는 PDF·웹 소개 수준이다 |
| ⚠️ 법무 | 마이데이터 사용 중 스크래핑을 겸하는 것 — 금융사 다 하지만 **검토를 받는 게 안전** → [[규제-법무-검토항목]] |

→ 사용자가 공단에서 직접 조회한 결과와 동일한 값을 받으므로 **우리가 국민연금 산식을 만들 필요가 없어졌다.**
단, 조기/연기·납입 기간을 바꿔보는 시뮬레이션은 별개다 (아래).

### 국민연금 변수 조정은 일단 고정값
- 조기/연기, 납입 종료 시점에 따라 금액이 바뀌는데, 이걸 계산하려면 **평균 소득 등 추가 변수**가 필요하다 (가입증명 서류에 있음)
- **결정 ([[이정은]]): 일단 종신 · 65세 수령 고정값.** 포털에서 온 월 예상 수령액만으로 충족
- 나중에 디벨롭하려면 수기 입력을 받거나, 안 받으면 고정값만 보게 하는 식으로 유연하게

## 그래서 문제를 어떻게 잡을 것인가 (퇴직·개인연금)

[[김동준]]의 프레임 전환:

> 검토를 **"받을 수 있나?"가 아니라 "우리가 계산할 때 책임 범위를 어디까지로 자를지"**로 잡는 게 맞다.

"60세부터 월 187만원" 같은 숫자는 **전부 우리가 식을 정리해서 계산해야 한다.**
즉 이 과제의 난점은 데이터 확보가 아니라 **가정을 어디까지 우리가 지느냐**다.

## 계산 원칙 제안 (김동준)
| 항목 | 방침 |
|---|---|
| 국민연금 | ~~산식 적용~~ → **스크래핑으로 공단 값을 그대로 받는다** (2026-09-11 변경). 개혁 반영도 공단 몫 |
| 퇴직·개인연금 | 적립금 + 가정치로 환산하되 **가정치를 화면에 노출** |
| 세후 계산 | API에 세액공제 여부가 없어 **근사 전제로 합의 필요** |
| 자사 계약 | 연금보험·퇴직연금은 내부 원장으로 정확히 나오므로 **기준선으로 활용** |

## 신뢰 구간 — 언제부터 의미 있는 숫자인가
국민연금 예상수령액은 **가입 10년차(120개월) 전후**부터 은퇴 설계 기준치로 기능한다. ([[한민우]] 조사)

| 연차 | 상태 |
|---|---|
| 1~5년 | 최소 가입 기준(10년) 미달. 단순 가산 추정치. 초봉이 평생 유지된다는 전제라 오차 큼 |
| 10년 전후 | 노령연금 수급 최소 요건 달성. '만 60세까지 납부 시 예상액'이 현실적 하한선 제시 |
| 15~20년 | B값(생애 평균 소득월액)·A값이 실제 패턴과 거의 일치. **오차 5~10% 이내** |

→ 2030 타겟에게는 예상수령액을 단정적으로 보여주면 안 된다는 근거가 된다.

## 마이데이터 운영에서 더 볼 것 (김동준)
- 신규 단독 앱이 마이데이터 허가 범위에 포함되는지
- 정기 전송 주기 (명세서 갱신 트리거)
- 재동의(1년)·철회 시 삭제 처리
- 예측 스냅샷 버전 관리 — **기준시점 + 가정치를 같이 저장**해야 전월 대비 변동 사유를 귀속할 수 있다

## PRD에 반영된 설계 원칙
마이데이터로 확인 불가한 항목(주택연금 전환, 자산 증여 등)은 사용자 직접 입력을 허용하되,
**"확인됨(마이데이터)"과 "본인 입력(미확인)"을 절대 섞지 않는다.** → [[평생보장소득-PRD]]
