# 마이데이터 연금정보

마이데이터로 **무엇이 오고 무엇이 안 오는지**. [[평생보장소득]]의 계산 설계를 좌우하는 제약.

- 초안 검토: [[김동준]] / 실측 담당: [[박정훈]]
  (실측 문서: `docs.google.com/document/d/18UnDY8qIvOlQAVA3PkGTkeUZt72zJsQ4b0wNUIoX94A`)

## 결론부터 — 예상수령액은 어디서도 안 온다

| 항목 | 오는 것 | 안 오는 것 |
|---|---|---|
| IRP · DC형 | 잔액, 평가금액, 납입원금, 연금개시(예정)일 | **예상수령액** |
| **DB형** | **보유 여부(Y/N) 하나뿐. 적립금도 없음** | 나머지 전부 |
| 연금저축(보험) | 연금개시일, 수령주기 | **예상 연금액** |
| 국민연금 | 납부내역(가입기간·기준소득월액) 수준 | **예상연금액** |

DB형은 보유 여부만 오므로 **평균임금 × 근속연수를 사용자에게 입력받거나 자체 산식이 필수**다.

## 그래서 문제를 어떻게 잡을 것인가

[[김동준]]의 프레임 전환:

> 검토를 **"받을 수 있나?"가 아니라 "우리가 계산할 때 책임 범위를 어디까지로 자를지"**로 잡는 게 맞다.

"60세부터 월 187만원" 같은 숫자는 **전부 우리가 식을 정리해서 계산해야 한다.**
즉 이 과제의 난점은 데이터 확보가 아니라 **가정을 어디까지 우리가 지느냐**다.

## 계산 원칙 제안 (김동준)
| 항목 | 방침 |
|---|---|
| 국민연금 | 공단과 **같은 가정**(현재 소득으로 60세까지 납부)으로 산식 적용 + **2026 개혁(소득대체율 43%)** 반영 |
| 퇴직·개인연금 | 적립금 + 가정치로 환산하되 **가정치를 화면에 노출** |
| 세후 계산 | API에 세액공제 여부가 없어 **근사 전제로 합의 필요** |
| 자사 계약 | 연금보험·퇴직연금은 내부 원장으로 정확히 나오므로 **기준선으로 활용** |

## 신뢰 구간 — 언제부터 의미 있는 숫자인가
국민연금 예상수령액은 **가입 10년차(120개월) 전후**부터 은퇴 설계 기준치로 기능한다. ([[한민우]] 조사)

| 연차 | 상태 |
|---|---|
| 1~5년 | 최소 가입 기준(10년) 미달. 단순 가산 추정치. 초봉이 평생 유지된다는 전제라 오차 큼 |
| 10년 전후 | 노령연금 수급 최소 요건 달성. '만 60세까지 납부 시 예상액'이 현실적 하한선 제시 |
| 15~20년 | B값(생애 평균 소득월액)·A값이 실제 패턴과 거의 일치. **오차 5~10% 이내** |

→ 2030 타겟에게는 예상수령액을 단정적으로 보여주면 안 된다는 근거가 된다.

## 마이데이터 운영에서 더 볼 것 (김동준)
- 신규 단독 앱이 마이데이터 허가 범위에 포함되는지
- 정기 전송 주기 (명세서 갱신 트리거)
- 재동의(1년)·철회 시 삭제 처리
- 예측 스냅샷 버전 관리 — **기준시점 + 가정치를 같이 저장**해야 전월 대비 변동 사유를 귀속할 수 있다

## PRD에 반영된 설계 원칙
마이데이터로 확인 불가한 항목(주택연금 전환, 자산 증여 등)은 사용자 직접 입력을 허용하되,
**"확인됨(마이데이터)"과 "본인 입력(미확인)"을 절대 섞지 않는다.** → [[평생보장소득-PRD]]
