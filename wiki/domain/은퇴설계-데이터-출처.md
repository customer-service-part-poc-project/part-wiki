# 은퇴설계 데이터 출처

[[평생보장소득]]이 계산에 쓰는 자산 항목을 **어디서 가져오고, 무엇이 막히고, 어떤 절차가 필요한지** 한눈에 보는 지도.
팀장 요청(9/14)으로 [[한민우]]가 정리했다. 파트 공유용 간략판 + 상세판(노션). **⚠️ 원본 미확보** — 아래는 9/15 스크럼 설명 기준.

## 문서 구조
| 축 | 내용 |
|---|---|
| 분류 | 자산 **카테고리별** |
| 출처 | 금융 마이데이터(빨강) / [[공공-마이데이터]](다른 색) / **출처 없음 → 수동 입력** |
| 부가 | 제약, 필요한 절차, 법무 검토 필요 여부 |

## 회의에서 언급된 항목
| 항목 | 출처 | 제약·비고 |
|---|---|---|
| 금융자산·연금계좌 (IRP·DC·연금저축 등) | 금융 마이데이터 | 보험업이라 **직접 사업자 불가 → 제휴사 경유.** 제휴사가 국민연금 조회를 겸할 수 있는지 법적 검토 ([[규제-법무-검토항목]] #13) |
| 국민연금 | 쿠콘 스크래핑 (확정 방향) · [[공공-마이데이터]] (후보) | → [[마이데이터-연금정보]] |
| [[주택연금]] | [[공공-마이데이터]] (후보) | 목적 승인이 관건 |
| **퇴직연금 DB형** | **없음 → 수동 입력** | 회사 정보를 알 수 없다. DC·IRP와 달리 수기. 입력값: **근속연수 + 최근 3개월 평균 임금** → 산식 ([[이강민]]). [[통합연금포털]]도 입력 방식이었던 것 같다 (확인필요) |
| **전세보증금** | **없음 → 수동 입력** | **확정일자 정보가 민간에 열려 있지 않다** |

> "HR플러스에는 (DB 정보가) 있나?" — "있다" ([[한민우]]·[[이강민]]). 확인필요: HR플러스가 사내 인사 시스템이라면 임직원 본인용일 뿐 고객 데이터 경로는 아니다.

## 설계 원칙과의 연결
수동 입력 항목은 **"본인 입력(미확인)"으로 표시**하고 마이데이터 확인값과 섞지 않는다 → [[사실과-계획-분리]], [[평생보장소득-PRD]]

## 확인필요
- 문서 원본 (간략판·상세판) — `raw/docs/`에 넣으면 전체 항목 표로 확장
- 공공 마이데이터로 실제 받을 수 있는 항목 목록
- DB형 산식의 기준 (통합연금포털 방식 참고)
