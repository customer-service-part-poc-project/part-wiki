# 고객서비스 파트 위키

파트에서 일어나는 일을 전부 던져 넣으면, LLM이 읽고 정리해서 **연결된 지식**으로 쌓아 두는 공간.
파트의 세컨드 브레인.

사람은 **자료를 넣고 질문한다.** 위키를 직접 쓰는 일은 거의 없다.
요약·정리·교차참조·페이지 갱신 같은 아무도 하기 싫은 일은 전부 LLM이 한다.

> 왜 굳이 이렇게 하나: 보통 문서함은 **찾을 수 있게만** 해 준다.
> 여기는 자료가 들어오는 순간 **기존 지식에 녹여 넣는다.**
> 회의록 20개를 뒤지지 않아도 "환불 기준 어떻게 바뀌었지?"에 한 페이지로 답이 나온다.
> 쌓일수록 좋아진다.

---

## 쓰는 법 — 이게 전부다

### 1. 자료를 넣는다
`raw/` 아래 적당한 폴더에 파일을 떨어뜨린다. 형식은 마크다운이면 가장 좋고, 아니어도 된다.

| 넣을 것 | 위치 |
|---|---|
| 회의록, 스크럼 노트 | `raw/meetings/` |
| VOC, 상담 이력, 리뷰, 설문 | `raw/voc/` |
| 통계, 리포트, 대시보드 캡처 | `raw/reports/` |
| 매뉴얼, 정책 원문, 공지 | `raw/docs/` |
| 슬랙·메일 스레드 | `raw/threads/` |
| 이미지·첨부 | `raw/assets/` |

### 2. 정리시킨다
```
raw/meetings/2026-09-11-정기회의.md 정리해줘
```
LLM이 읽고 → 요약을 먼저 보고하고 → 소스 페이지를 만들고 →
관련된 위키 페이지 열 몇 장을 같이 고친다. 마지막에 무엇을 바꿨는지 알려준다.

### 3. 물어본다
```
배송지연 클레임 대응 기준 지금 어떻게 돼 있어?
CSAT 최근 3개월 추이랑 원인 정리해줘
A업체 관련해서 지금까지 나온 이슈 다 모아줘
```
답에는 항상 `[[출처 페이지]]`가 붙는다. 쓸 만한 답은 `wiki/notes/`에 페이지로 남는다.

### 4. 가끔 점검시킨다
```
위키 점검해줘
```
모순·낡은 내용·빠진 페이지·고아 페이지를 찾아 보고한다. 다음에 뭘 채우면 좋을지도 알려준다.

---

## 어디에 뭐가 있나

```
raw/        원본. 사람이 넣고, LLM은 읽기만 한다.
wiki/       LLM이 쓰는 지식. 여기를 읽으면 된다.
index.md    위키 전체 목차. 뭐가 있는지 여기서 본다.
log.md      무슨 작업이 언제 있었는지.
CLAUDE.md   LLM 운영 규약. 정리 방식을 바꾸고 싶으면 여기를 고친다.
```

`wiki/` 안쪽:

| 폴더 | 들어가는 것 |
|---|---|
| `overview.md` | 파트 전체 한 장 요약. **여기서 시작한다.** |
| `people/` `orgs/` | 파트원, 유관부서, 외주사·솔루션 업체 |
| `processes/` | 업무 절차 — 인입, 분류, 처리, 에스컬레이션 |
| `policies/` | 응대 기준 — 환불, 보상, 악성 응대 |
| `systems/` | 상담 솔루션, CRM, 어드민, 내부 툴 |
| `issues/` | 반복 이슈·장애·클레임 유형 |
| `metrics/` | CSAT, FCR, AHT, 인입량 등 지표와 추이 |
| `projects/` | 진행 중인 개선 과제 |
| `decisions/` | 무엇을 왜 그렇게 정했는지 |
| `glossary/` | 내부 용어·은어·코드값 |
| `sources/` | 원본 1건당 요약 1장 |
| `notes/` | 질문에 답하며 만들어진 분석·비교 |

---

## 두 가지 규칙만 지키면 된다

**1. `raw/`는 건드리지 않는다.** 원본은 불변. 고칠 게 있으면 새 파일을 넣는다.

**2. 고객 개인정보는 `wiki/`에 올라가지 않는다.**
실명은 `고객A`, 연락처는 `010-****-****`, 주문번호는 뒷자리만.
케이스는 "누구"가 아니라 **"어떤 유형을 어떻게 처리했는지"**로 남는다.
사내 구성원 이름은 실명으로 쓴다 — 업무 기록이니까.

> `raw/`에 원본 개인정보가 들어가는 건 어쩔 수 없다.
> 이 저장소를 외부에 공개하거나 사외 공유하지 않는 전제로 운영한다.

---

## Obsidian으로 보기

이 폴더를 Obsidian Vault로 열면 훨씬 낫다.

- `[[링크]]`가 살아나고, **그래프 뷰**로 지식이 어떻게 연결됐는지 한눈에 보인다.
- 링크는 있는데 페이지가 없는 항목 = 다음에 채울 것.
- **Obsidian Web Clipper** 확장으로 웹 문서를 `raw/`에 바로 마크다운으로 떨군다.
- 첨부 경로는 설정 → 파일 및 링크 → 첨부 파일 폴더를 `raw/assets/`로.

한쪽에 Obsidian, 한쪽에 LLM 띄워 놓고 쓰면 된다.
LLM이 고치는 걸 실시간으로 보면서 링크를 따라다닐 수 있다.

## 배경

이 저장소는 [`llm-wiki.md`](./llm-wiki.md)의 패턴을 고객서비스 파트에 맞게 구현한 것이다.
원래 문서는 추상적인 아이디어만 설명하고, 구체적인 구조는 각자 도메인에 맞춰 만들라고 한다.
여기서는 그걸 CS 파트용으로 못 박아 놨다 — 자세한 규약은 [`CLAUDE.md`](./CLAUDE.md)에 있다.

일하는 방식이 규약과 안 맞으면 `CLAUDE.md`를 고치면 된다. 그게 이 시스템의 설정 파일이다.
