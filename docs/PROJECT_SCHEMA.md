# 프로젝트 카드 스키마 (정본)

`data/projects/{과제명}.json` 의 형식. `scripts/build_site.py` 가 빌드 전에 검증하고,
어긋나면 **해당 파일만 건너뛰고 이유를 출력**한다 (프로필과 같은 방식).

프로젝트 카드는 **위키 `wiki/projects/` 페이지의 공개용 요약**이다. 위키 본문을 자동으로 내보내지 않는다.
사람(또는 LLM)이 위키를 읽고 이 JSON 을 손으로 쓴다. 그래서 **무엇을 싣지 않을지**가 스키마의 절반이다.

---

## 전체 구조

```json
{
  "schema_version": 1,
  "name": "평생보장소득",
  "title": "평생 보장소득 은퇴설계 플랫폼",
  "part": "고객서비스파트",
  "codename": "PLUS",
  "status": "진행중",
  "order": 1,
  "phase": "사업계획 보고",
  "target": "2027-07 출시 1차안",
  "generated": "2026-09-15",
  "sources": ["wiki:projects/평생보장소득"],

  "summary": "한 문장 정의. 카드와 상세 상단에 나간다",
  "tagline": "슬로건 한 줄 (없으면 빈 문자열)",
  "badges": ["주력 과제", "웹 우선 검토", "출시 1차안 2027-07"],

  "milestones": [
    {"label": "1차 보고 (부사장)", "date": "2026-08-20", "state": "done"},
    {"label": "부회장 보고",        "date": "2026-09 중", "state": "doing"},
    {"label": "출시 1차안",         "date": "2027-07",    "state": "todo"}
  ],

  "workstreams": [
    {"area": "보고", "state": "진행중", "note": "2회 완료. 3차 사업계획(안) 팀장 리뷰"}
  ],

  "members": [
    {"name": "이강민", "role": "총괄·보고"}
  ],

  "next": ["다음에 할 일 2~5개"],

  "recent": [
    {"date": "2026-09-15", "note": "최근 변화. 최신이 위"}
  ]
}
```

---

## 필드 규칙

| 필드 | 필수 | 규칙 |
|---|---|---|
| `name` | ✅ | 파일명과 같아야 한다. 위키 페이지 파일명(`wiki/projects/{name}.md`)과 맞춘다 |
| `title` | ✅ | 카드와 상세에 찍는 과제명 |
| `status` | ✅ | `준비` · `진행중` · `보류` · `완료` 중 하나. 목록은 이 순서로 정렬된다 |
| `order` | | 같은 상태 안의 정렬. 작을수록 앞. 없으면 100 |
| `phase` | | 지금 단계 한 마디 (예: `사업계획 보고`, `개발 검수`) |
| `target` | | 출시·완료 목표. 자유 텍스트 |
| `codename` | | 내부 코드명. 없으면 빈 문자열 |
| `badges` | | 카드 칩. **3개까지만** 표시된다 |
| `milestones[].state` | ✅ | `done` · `doing` · `todo` 중 하나 |
| `milestones[].date` | | 자유 텍스트. `미정`, `2026-09 중` 도 된다 |
| `workstreams[].state` | | 자유 텍스트. `완료`·`진행`·`검토`·`대기`·`보류`·`미착수` 낱말이 들어 있으면 색이 붙는다 |
| `members[].name` | ✅ | 파트원 실명. 프로필 카드가 있으면 상세에서 링크된다 |
| `recent` | | 최신이 위. 화면도 그 순서로 찍는다 |

### 진행률은 사람이 적지 않는다
카드와 상세의 진행률 막대는 **`milestones` 의 `done` 수 / 전체 수**다.
`progress: 60` 같은 칸은 없다. 근거 없는 수치를 싣지 않기 위해서다 (CLAUDE.md §3 "사실과 추론의 구분").

"다음" 은 `doing` 인 첫 마일스톤, 없으면 `todo` 인 첫 마일스톤이다.

## 싣지 않는 것 — 이 사이트는 public 이다

프로젝트 카드는 프로필과 같은 금지 규칙을 탄다 (→ `docs/PRIVACY.md`).
빌드가 JSON 전체를 훑어 걸리면 **그 파일만 건너뛴다.**

| 싣지 않는다 | 대신 |
|---|---|
| 임원·타부서 실명 | 직책만 (`부사장`, `팀장`) |
| 사내 URL · 노션·구글문서·SharePoint 링크 | 링크 없이 문서 이름만 |
| 법무·준법 검토 **항목** | "법무 검토 진행 중" 같은 **상태**만 |
| 경쟁사 분석 · 시장 수치 · 전략 근거 | 싣지 않는다. 위키 본문에 있다 |
| 벤더·계약 상대 이름 | "외부 데이터 사업자" 처럼 일반화 |
| 회의 발언 원문 인용 | `raw_quote`·`quotes`·`samples_*` 키는 빌드가 거부한다 |

> 판단 기준: **회사 밖 사람이 읽어도 곤란하지 않은가.** 애매하면 뺀다. 위키에는 그대로 남아 있다.

## 검증 — 빌드가 거부하는 조건

`scripts/build_site.py` 의 `validate_project` 가 확인한다.

1. `schema_version == 1`
2. `name` 이 파일명과 일치
3. `title` 이 비어 있지 않음
4. `status` 가 네 값 중 하나
5. `milestones[].state` 가 세 값 중 하나
6. **금지 키 없음**: `samples_*`, `raw_quote`, `quotes`, `gender`, `성별`
7. **금지 패턴 없음** (→ `docs/PRIVACY.md`)

프로젝트 JSON 이 0건이거나 전부 거부돼도 **빌드는 성공한다.** 프로젝트 섹션만 빠진다.

## 갱신 시점
`wiki/projects/` 페이지가 바뀌면 이 JSON 도 같이 본다. 특히 `milestones`·`recent`·`generated`.
위키와 카드가 어긋나면 카드 쪽이 낡은 것이다 — 위키가 정본이다.
