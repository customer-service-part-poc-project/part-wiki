**마이데이터 연금 항목**
- IRP·DC형 : 잔액·평가금액·납입원금·연금개시(예정)일까지 옴, 예상수령액 X
- DB형 : 보유 여부(Y/N) 하나만 옴, 적립금도 없음 → 평균임금×근속연수 사용자 입력 or 자체 산식 필수
- 연금저축(보험) : 연금개시일·수령주기 O, 예상 연금액 X
- 국민연금 : 납부내역(가입기간·기준소득월액) 수준으로 알고 있어요. 예상연금액은 없어보입니다.
- 검토: 예상수령액은 어디서도 안 오고, 말씀하신 대로 "60세부터 월 187만원"은 전부 우리가 식을 정리해서 계산해야 할것 같아요. 때문에 검토를 "받을 수 있나?"가 아니라 "우리가 계산할 때 책임 범위를 어디까지로 자를지"로 잡는 게 맞을 것 같아요.
- 제안 : 국민연금은 공단과 같은 가정(현재 소득으로 60세까지 납부)으로 산식 적용 + 2026 개혁(소득대체율 43%) 반영 / 퇴직·개인연금은 적립금+가정치 환산하고 가정치를 화면에 노출 / 세후 계산은 API에 세액공제 여부가 없어서 근사 전제로 합의 필요
- 자사 계약(연금보험·퇴직연금)은 내부 원장으로 정확히 나오니 기준선으로 활용

**통합연금포털**
- 외부 API 없음 → 위임 로그인(스크래핑, 교보 방식) or 사용자 직접 입력/캡처 둘 중 하나
- 스크래핑은 마이데이터 사업자 스크래핑 제한(신용정보법 22조의9) 저촉 여부 준법 검토 필요 (교보는 어떤 근거인지 확인)
- 3영업일 지연 → "즉시 결과(자체 계산) → 포털 값 도착 시 보정" 2단계 구조 권장

**부부 합산**
- 흐름 동의. 배우자 간 공유는 제3자 제공 동의(양방향) + 마이데이터 정보 목적 외 이용 이슈 → 준법 검토
- 이탈 방지 : 연동 전에 배우자 최소 입력 모드(생년·국민연금 예상액·퇴직 예정 시점)로 결과 먼저 → 정식 연동은 결과 화면의 "정확도 올리기"로
- 부부 단위 필수 근거 : 건보료 세대 단위 부과·피부양자 판정 / 주택연금 연소자 기준 / 국민연금 유족·분할연금
- 데이터 모델 : 가구 ↔ 구성원 ↔ 공유동의(상태·범위·시점). 해제 시 합산 뷰만 무효화(원본은 각자 유지), 이혼=분할연금(혼인 5년↑)·사망=유족연금 시나리오로 처리

**주택연금**
- HF 오픈API "주택연금 예상월지급금 조회" 있음 : 주택가격·소유자 만나이·배우자 만나이 → 지급방식별 월지급금·인출한도
- 단 입력이 주소가 아니라 주택가격 → 주소→가격 변환은 우리 몫
- 가입자격은 공시가격(부부합산 12억↓), 월지급금은 시세 기준(부동산원→KB→공시가격→감정평가 순, 12억 초과분은 12억 산정, 연소자 기준)
- 공시가격 API만 붙이면 과소 산출 → 시세 확보 경로(부동산원/KB 제휴, 실거래가 근사, MVP는 사용자 입력)가 진짜 검토 과제. 월지급금은 매년 재산정이라 유효기간 표시 필요
